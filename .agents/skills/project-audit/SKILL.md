# Project Audit

At the start of a work session, read [AGENTS.md](../../../AGENTS.md), [audit_protocol.md](../../../audit_protocol.md), and the latest entries in [audit_log.md](../../../audit_log.md).

## Follow the audit protocol
Use the team's protocol when explaining sources, checking data definitions, reviewing queries, and assessing results. If a meaningful human check suggests a useful new practice, propose one short protocol addition and wait for the team's approval before editing it.

## Maintain the audit log
The log records meaningful human checks of the agent's work: checking a source or schema, verifying a calculation, challenging an assumption, or correcting an interpretation. Confirmed correct work may count too.

Do not log routine approvals, ordinary clarification, the agent's own checks, or checks of human work. Do not invent a check, outcome, date, source, or reviewer. If the team reports a check performed elsewhere without evidence, say so and mark it pending when appropriate.

Before adding an entry:
1. Read earlier entries and find the next unused number.
2. Show the proposed entry and category to the team.
3. Add it only after the team approves.
4. Keep entries short and identify who did the work and who checked it.

Use the categories and columns in audit_log.md. Preserve old entries and never reuse removed numbers. If an issue is resolved later, add a dated resolution that refers to the earlier entry rather than erasing history.

This skill does not authorize queries, cloud spending, publishing, commits, or unrelated edits.
