# Project Audit

At session start, read [AGENTS.md](../../../AGENTS.md), [audit_protocol.md](../../../audit_protocol.md), [decisions.md](../../../decisions.md), and the latest entries in [audit_log.md](../../../audit_log.md).

## Support student verification

Follow the protocol's small analysis cycle. Invite the student's reasoning before major choices and their interpretation before supplying the agent's interpretation. Offer a hint or worked example when needed. Use reasoning already supplied and keep pauses focused on meaningful analytical decisions.

The log records **the human checking the agent's work**: checking a source or schema, independently verifying a calculation, testing an assumption, or correcting an interpretation. Confirmed correct work can count. The agent may help design a check and resolve an issue, but describe each person's actual contribution.

Skip routine approvals, wording feedback, ordinary clarification, the agent's own checks, and checks of human work. An upload, a source request, an accepted decision, or a student explanation alone does not establish verification. Record consequential choices and reasons in decisions.md; use the audit log only when an actual human check also occurred.

## Propose and add entries

When a substantial human check is worth logging, flag it without waiting to be asked.

1. Read relevant earlier entries to avoid duplicates and identify the next unused number. Never reuse removed numbers.
2. Choose one existing category: Caught an error, Verified a claim, Separated fact from opinion, Changed the analysis, or Improved the agent's instructions.
3. Show the proposed entry and category to the team. Add it only after approval of that entry.
4. Use the log's five columns. Start the agent column with "Agent" and the check column with the actual person's name. Describe the claim, the human's method/evidence, and the outcome briefly; link sources or queries/results when available.
5. Update the category's summary count and check that it matches the entries.

Do not invent a reviewer, review, understanding, result, date, source, or learning progress. If a human reports a check performed elsewhere without available evidence, identify it as reported and explain the evidence limit. A source request does not prove the source was checked; a preview does not prove a whole-column property. Mark unresolved outcomes pending.

Preserve old entries. Add a dated resolution referring to an earlier entry when an issue is resolved later; keep the original history.

## Protocol changes and scope

When a meaningful human check suggests a useful new practice, propose one short protocol addition and apply it after team approval. Avoid turning every interaction into a rule.

This skill maintains audit records. It does not authorize queries, cloud spending, publishing, commits, or unrelated edits. Follow AGENTS.md and the user's actual authorization for those actions.
